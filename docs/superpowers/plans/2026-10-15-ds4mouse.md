# DS4Mouse Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans. Track steps with checkboxes. The user approved the spec, directed execution, and asked to accelerate. Implement directly in this session without further design checkpoints. Do not commit or push.

**Goal:** Deliver a working native Bluetooth DualShock 4 mouse with a menu bar app, mouse mapping GUI, CLI, and tests.

**Architecture:** One app owns HID input, gesture recognition, mouse events, and saved settings. A CLI communicates with that app over a private local socket. Pure Swift logic handles parsing, configuration, and gestures independently of macOS adapters.

**Tech stack:** Swift 6, Swift Package Manager, AppKit/SwiftUI, IOKit, CoreGraphics, Swift Testing.

**Spec:** [Approved design](../specs/2026-10-14-ds4mouse-design.md).

## Constraints and review focus

- macOS 13 deployment target; initially verify on the connected arm64 Mac.
- No runtime package dependencies, privileged helper, exclusive device seizure, telemetry, keyboard mappings, commits, or pushes.
- Start disabled; save mappings; release held output on disable, disconnect, sleep, or configuration changes.
- Review malformed reports, reused contact slots, queued input after disabling, overlapping holds, and simultaneous CLI requests.
- No signing identity is available. Deliver a local build and documented release prerequisites without claiming notarization.

## Validation commands

Run from the project root:

```sh
./scripts/test.sh
swift build -c release
swift format lint --strict --recursive Sources Tests Package.swift
./scripts/build-app.sh
./dist/DS4Mouse.app/Contents/MacOS/ds4mouse doctor --json
./dist/DS4Mouse.app/Contents/MacOS/ds4mouse status --json
```

Hardware checks must cover touch down/up, both fingers, click/drag, changing mappings from GUI and CLI, disable during drag, reconnect, and sleep/wake. Record unperformed checks instead of treating automated tests as physical verification.
